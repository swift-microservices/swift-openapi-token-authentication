# Repository guidelines

This package authenticates clients generated by Swift OpenAPI Generator with access and refresh
tokens. Read this before changing anything.

## What this package is

- One product, `OpenAPITokenAuthentication`: `AuthenticationSession`, an actor that holds
  credentials and shares in-flight sign-in and refresh work; `AuthenticationMiddleware`, an
  OpenAPI `ClientMiddleware` that attaches the bearer token and refreshes and retries a
  replayable request once; the `AuthenticationClient`, `AuthenticationResponse`, and
  `AuthenticationStorage` protocols an application implements; and `InMemoryAuthenticationStorage`.
- It depends only on swift-openapi-runtime, with `traits: []`, and swift-http-types. It is a
  client library: it runs in apps and SDKs as well as servers, so it declares the Apple
  platforms beside macOS 15. It does not depend on swift-authentication.
- `accessToken()` stays strict; only the middleware's `.ifAvailable` policy sends a request
  anonymously when the session requires sign-in.

## What does not belong here

- Verifying tokens or reading claims. Servers verify the token; on a Swift server the
  swift-authentication packages do it.
- A concrete secure store such as a Keychain wrapper. Applications implement
  `AuthenticationStorage` for their platform.
- The API's own sign-in and refresh calls. Applications implement `AuthenticationClient` over
  their generated client.

## Swift

- Swift 6.3, strict concurrency, `Sendable` everywhere it is meaningful.
- Tests use Swift Testing with in-memory doubles: token attachment, refresh and single retry,
  replayable and single-use bodies, both policies, shared in-flight work, rejected and temporary
  refresh failures, logout and replacement sign-in cancelling pending work, and state observation.
- Doc comments on every public declaration; the DocC catalog is the long-form explanation and
  must build without warnings.
- Use the checked-in `.swift-format`, copied exactly from apple/swift-temporal-sdk at
  `508797b5468dbc532f77c317bf9df0cb3231f5c1`: four-space indentation, 150-column lines,
  and ordered imports. Format all tracked Swift files, including `Package.swift`, and run
  `swift-format lint --strict`. Public documentation remains a repository requirement even
  though this formatter does not enforce it.
- File headers use the compact license format documented below.

## Releases

- Every pull request carries exactly one label: `⚠️ semver/major`, `🆕 semver/minor`,
  `🔨 semver/patch`, or `semver/none`. The label check blocks merging without one.
- Releases are GitHub Releases, created by the Auto Release workflow: run it by hand on `main`
  and it computes the next version from the labels of the pull requests merged since the last
  release, tags it, and writes the notes from `.github/release.yml`. A major bump is refused
  there and is cut by hand.
- Consumers pin by tag, never by branch or path.
