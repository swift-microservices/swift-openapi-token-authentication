# OpenAPI Token Authentication

Access-token authentication and automatic refresh for clients generated by
[Swift OpenAPI Generator](https://github.com/apple/swift-openapi-generator).

An `AuthenticationSession` actor manages credentials and shares in-flight authentication
work between callers. `AuthenticationMiddleware` adds bearer tokens to requests and
refreshes authentication before retrying an HTTP 401 response once.

## Requirements

Swift 6.3 or later. Supports Linux and macOS 15, iOS/Mac Catalyst/tvOS 18,
watchOS 11, and visionOS 2 or later.

## Installation

Add the package to your `Package.swift` dependencies:

```swift
.package(
    url: "https://github.com/swift-microservices/swift-openapi-token-authentication.git",
    from: "0.1.0"
),
```

Then add the library to your target:

```swift
.product(name: "OpenAPITokenAuthentication", package: "swift-openapi-token-authentication"),
```

## Usage

Implement `AuthenticationClient` with your API's login and refresh calls. Its response
must conform to `AuthenticationResponse`, providing access and refresh tokens and their
expiration dates. Use an authentication client without this middleware for those
calls to avoid waiting on its own session.

```swift
import OpenAPITokenAuthentication

let session = AuthenticationSession(
    client: authenticationClient,
    storage: InMemoryAuthenticationStorage<YourAuthenticationResponse>()
)

try await session.authenticate(credentials: credentials)

let client = Client(
    serverURL: serverURL,
    transport: transport,
    middlewares: [AuthenticationMiddleware(session: session)]
)
```

Share a session across clients using the same credentials. Access tokens refresh on
demand within 30 seconds of expiration; customize this with `refreshLeeway`.
Provide an `AuthenticationStorage` implementation if credentials must survive restarts.

The middleware refreshes on HTTP 401 by default. Customize this with
`refreshableStatusCodes` or a response predicate:

```swift
AuthenticationMiddleware(session: session) { response, _ in
    response.status == .unauthorized
        && response.headerFields[.wwwAuthenticate]?.contains("invalid_token") == true
}
```

Requests with single-use bodies are never retried. Only overlapping refreshes share
work; a later rejected response can trigger another refresh. Cancel outstanding API
requests before switching accounts, or use separate sessions for separate accounts.

The session also works without middleware:

```swift
let token = try await session.accessToken()
let refreshedToken = try await session.newAccessToken()
await session.logout()
```

### Observing state

```swift
let observation = Task {
    for await state in await session.states() {
        print(state) // unauthenticated, authenticating, authenticated, or refreshing
    }
}

observation.cancel()
```

Each listener receives the current state followed by changes, buffering only the latest
state. Cancelling observation does not cancel authentication.

### Errors and cancellation

Classify rejected credentials in your authentication client with
`AuthenticationClientError(.invalidCredentials)` or `.invalidRefreshToken`, optionally
preserving the API error in `underlyingError`. Other errors propagate unchanged.

Missing, expired, or rejected refresh credentials clear the session and throw
`AuthenticationSessionError.userAuthenticationRequired`. Temporary refresh failures
preserve valid refresh credentials so a later call can retry.

Cancelling an endpoint request does not cancel shared authentication work or immediately
interrupt its wait. Logout and replacement login cancel pending work and prevent stale
results from restoring credentials.
