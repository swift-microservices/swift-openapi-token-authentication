Access-token authentication and automatic refresh for clients generated by
[Swift OpenAPI Generator](https://github.com/apple/swift-openapi-generator). Sign a person in once,
and every request carries a bearer token that is refreshed before it expires and after the server
rejects it.

- 🔐 Bearer tokens, on-demand refresh and a single retry after HTTP 401, as one client middleware
- 📦 Depends only on swift-openapi-runtime (default traits off) and swift-http-types
- 📱 Runs in apps, SDKs and servers: Linux, macOS, iOS, Mac Catalyst, tvOS, watchOS and visionOS
- 🔧 Built with Swift 6.3 and strict concurrency

## 📖 Overview

Your API has a login operation and a refresh operation, and every other operation wants an
`Authorization: Bearer …` header. This package keeps those tokens for you. An
`AuthenticationSession` actor holds the credentials and makes the login and refresh calls you
describe in an `AuthenticationClient`. An `AuthenticationMiddleware` on your generated client asks
the session for a token before each request and, when the server rejects it, refreshes once and
retries.

Verifying the token is the server's business. On a Swift server, the
[swift-authentication](https://github.com/swift-microservices/swift-authentication) packages do it.

**Key Features:**
- 🤝 **Shared work**: while a login or refresh is in flight, every caller waits on that same work
  instead of starting its own, so many concurrent requests cause one refresh.
- ⏱️ **Refresh ahead of expiry**: an access token is refreshed on demand within 30 seconds of its
  expiration (configurable with `refreshLeeway`).
- 🔁 **One safe retry**: a rejected request is refreshed and retried once, and only when its body
  can be sent again.
- 🌐 **Anonymous fallback**: the `.ifAvailable` policy sends a request without a token when nobody
  is signed in, for endpoints that accept both.
- 💾 **Your storage**: keep credentials in memory with `InMemoryAuthenticationStorage`, or
  implement `AuthenticationStorage` over the Keychain or another secure store to survive restarts.
- 👀 **Observable state**: `states()` streams `unauthenticated`, `authenticating`, `authenticated`
  and `refreshing` for your UI.

## 🏁 Getting Started

### Prerequisites

- Swift 6.3 or later
- Linux, macOS 15, iOS 18, Mac Catalyst 18, tvOS 18, watchOS 11 or visionOS 2

To install or upgrade Swift, see https://www.swift.org/install/.

### Adding as a dependency

Add the package, then the `OpenAPITokenAuthentication` product to the target that holds your
generated client:

```swift
dependencies: [
    .package(url: "https://github.com/swift-microservices/swift-openapi-token-authentication.git", from: "1.0.0"),
],
targets: [
    .target(
        name: "MyAPIClient",
        dependencies: [
            .product(name: "OpenAPITokenAuthentication", package: "swift-openapi-token-authentication"),
        ]
    ),
]
```

### Usage

The examples below assume your OpenAPI document has two operations:

- `login`, taking a username and password and returning `200` with a `TokenPair`, or `401`
- `refresh`, taking a refresh token and returning `200` with a `TokenPair`, or `401`

where the `TokenPair` schema has `accessToken`, `refreshToken`, `accessTokenExpiration` and
`refreshTokenExpiration` properties (the two expirations formatted as `date-time`). `Client`,
`Components` and `Operations` are the types Swift OpenAPI Generator makes from it; rename the
operations and schemas to match yours.

#### 1. Describe your API's login and refresh

Conform your token schema to `AuthenticationResponse`. With the property names above, the
generated type already has everything it needs; otherwise wrap it in a small type of your own.

Then implement `AuthenticationClient` over the generated login and refresh operations. Tell the
session which failures mean "sign in again" by throwing `AuthenticationClientError`; let every
other error propagate unchanged.

```swift
import OpenAPITokenAuthentication

extension Components.Schemas.TokenPair: AuthenticationResponse {}

struct APIAuthenticationClient: AuthenticationClient {
    struct Credentials: Sendable {
        var username: String
        var password: String
    }

    // A generated client *without* AuthenticationMiddleware, so login and refresh
    // never wait on the session they serve.
    let client: Client

    func authenticate(credentials: Credentials) async throws -> Components.Schemas.TokenPair {
        let output = try await client.login(
            body: .json(.init(username: credentials.username, password: credentials.password))
        )
        if case .unauthorized = output {
            throw AuthenticationClientError(.invalidCredentials)
        }
        return try output.ok.body.json
    }

    func refreshAuthentication(refreshToken: String) async throws -> Components.Schemas.TokenPair {
        let output = try await client.refresh(body: .json(.init(refreshToken: refreshToken)))
        if case .unauthorized = output {
            throw AuthenticationClientError(.invalidRefreshToken)
        }
        return try output.ok.body.json
    }
}
```

`AuthenticationClientError` can also keep the API's own error:
`AuthenticationClientError(.invalidCredentials, underlyingError: error)`. Credentials can be
anything `Sendable`, such as a pairing code instead of a password.

#### 2. Keep the tokens in a secure store

The session reads credentials from its storage when it is created and writes them after every
login and refresh. `InMemoryAuthenticationStorage` forgets them when the process ends; to keep a
person signed in across launches, implement `AuthenticationStorage` over your platform's secure
store. On Apple platforms that is the Keychain:

```swift
import Foundation
import OpenAPITokenAuthentication
import Security

struct KeychainAuthenticationStorage: AuthenticationStorage {
    var service = "com.example.app.tokens"

    func set(_ response: Components.Schemas.TokenPair) {
        guard let data = try? JSONEncoder().encode(response) else { return }
        wipe()
        let item: [String: Any] = [
            kSecClass as String: kSecClassGenericPassword,
            kSecAttrService as String: service,
            kSecAttrAccessible as String: kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly,
            kSecValueData as String: data,
        ]
        SecItemAdd(item as CFDictionary, nil)
    }

    func get() -> Components.Schemas.TokenPair? {
        let query: [String: Any] = [
            kSecClass as String: kSecClassGenericPassword,
            kSecAttrService as String: service,
            kSecReturnData as String: true,
            kSecMatchLimit as String: kSecMatchLimitOne,
        ]
        var result: CFTypeRef?
        guard SecItemCopyMatching(query as CFDictionary, &result) == errSecSuccess,
            let data = result as? Data
        else { return nil }
        return try? JSONDecoder().decode(Components.Schemas.TokenPair.self, from: data)
    }

    func wipe() {
        let query: [String: Any] = [
            kSecClass as String: kSecClassGenericPassword,
            kSecAttrService as String: service,
        ]
        SecItemDelete(query as CFDictionary)
    }
}
```

Stored credentials whose refresh token is missing or expired are wiped when the session is
created, and the session starts signed out.

#### 3. Create the session and add the middleware

```swift
import Foundation
import OpenAPITokenAuthentication
import OpenAPIURLSession  // or any other ClientTransport

let serverURL = URL(string: "https://api.example.com")!
let transport = URLSessionTransport()

// Login and refresh go through a client without the middleware...
let session = AuthenticationSession(
    client: APIAuthenticationClient(client: Client(serverURL: serverURL, transport: transport)),
    storage: KeychainAuthenticationStorage()
)

// ...and every other call goes through a client with it.
let client = Client(
    serverURL: serverURL,
    transport: transport,
    middlewares: [AuthenticationMiddleware(session: session)]
)

try await session.authenticate(credentials: .init(username: "ada", password: "correct horse"))

// Each request now carries `Authorization: Bearer …`, refreshed as needed.
let output = try await client.getProfile()  // one of your own operations
```

Share one session across every client that uses the same credentials, and use separate sessions
for separate accounts. Before switching accounts on one session, cancel outstanding API requests.
`authenticate(credentials:)` replaces any previous credentials, and `logout()` removes them; both
cancel pending login or refresh work so its result can't restore old credentials.

#### Endpoints that also accept anonymous requests

Authentication is required by default: with nobody signed in, the middleware throws
`AuthenticationSessionError.userAuthenticationRequired`. For endpoints that work either way, attach
a token only when one is available:

```swift
let publicClient = Client(
    serverURL: serverURL,
    transport: transport,
    middlewares: [AuthenticationMiddleware(session: session, policy: .ifAvailable)]
)
```

The middleware still waits for any in-flight login or refresh first. If the lookup then throws
`userAuthenticationRequired` (signed out, or the refresh credentials turned out to be expired or
rejected), it sends the request unchanged: no `Authorization` header is added, existing headers
are kept, and the response, even a 401, is returned without a refresh or retry. Other lookup
errors, such as transport failures and cancellation, still propagate. Once a token is attached,
the usual refresh and retry applies, and a failure is never retried anonymously. The server still
enforces authorization. `accessToken()` itself stays strict, and the policy doesn't relax how the
session validates a login or stored credentials.

#### Choosing which responses trigger a refresh

The middleware refreshes on HTTP 401. Pass other statuses, or decide from the response itself:

```swift
AuthenticationMiddleware(session: session, refreshableStatusCodes: [.unauthorized, .forbidden])

AuthenticationMiddleware(session: session) { response, _ in
    response.status == .unauthorized
        && response.headerFields[.wwwAuthenticate]?.contains("invalid_token") == true
}
```

A request is retried once, and never when its body is single-use. Only overlapping refreshes
share work, so a later rejected response can trigger another refresh.

#### Using the session directly

The session works without the middleware too, for calls that don't go through the generated
client:

```swift
let token = try await session.accessToken()            // cached, or refreshed near expiry
let refreshedToken = try await session.newAccessToken() // refresh now, or join one in flight
await session.logout()
```

#### Observing sign-in state

```swift
let observation = Task {
    for await state in await session.states() {
        print(state)  // unauthenticated, authenticating, authenticated or refreshing
    }
}

observation.cancel()
```

Each stream receives the current state, then every change; a slow observer gets only the latest.
The stream stays open across login and logout, and cancelling it doesn't cancel authentication.

#### Errors and cancellation

Missing, expired or rejected refresh credentials clear the session and its storage and throw
`AuthenticationSessionError.userAuthenticationRequired`: show your sign-in screen. A temporary
refresh failure, such as a network error, propagates and keeps valid refresh credentials so a later
call can try again. Cancelling an API request doesn't cancel the shared login or refresh it waits
on, and doesn't interrupt that wait immediately.
